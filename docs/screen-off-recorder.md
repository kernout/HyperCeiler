# 音量上快捷录音

## 行为与作用域

入口为 **系统框架 → 音量 → 音量上快捷录音**，默认关闭。兼容保留偏好键 `prefs_key_system_framework_volume_screen_off_recorder`，键名不表示仅熄屏可用。只需勾选 Android 系统框架（Android 系统 / `android` / `system`，运行于 `system_server`）作用域，无需勾选录音机、SystemUI，也不调用原生录音机。

| 录音状态 | 屏幕状态 | 音量上快捷键 |
| --- | --- | --- |
| 未录音（idle） | 熄屏 | 快速双击开始 |
| 未录音（idle） | 亮屏 | 快速三击开始 |
| 录音中（recording） | 熄屏或亮屏 | 快速双击停止并保存 |

切换屏幕状态不结束录音。熄屏按键操作不应唤屏，触发、录音和停止均不应启动 Activity。媒体播放和通话期间也允许触发快捷键，不以播放或通话状态拦截；系统麦克风策略仍可能使录音静音或拒绝录音，不能保证通话同时录音成功。现有音量下相机逻辑保持不变。

录音由 HyperCeiler 自身的非导出服务 `com.sevtinge.hyperceiler.recording.ScreenOffRecordingService` 执行。仅使用麦克风录制外部声音，不采集系统内部音频或通话下行，不使用播放捕获或通话音源；手机扬声器发出的声音仍可能被麦克风拾取。

录音通知仅显示状态，没有停止按钮；功能提供的手动结束入口只有音量上双击。保留 microphone 类型前台服务通知及系统麦克风指示，不隐藏通知或隐私提示。现有单次最长 2 小时自动停止保存，以及错误、撤权等情况下的终止和资源清理继续保留，这些属于自动保护，不是额外手动关闭入口。

文件保存至 `/storage/emulated/0/Download/oppose`。新录音通过 `MediaStore.Downloads` 写入共享下载目录（`Download/oppose`），无需存储权限或 `MANAGE_EXTERNAL_STORAGE`；不为本功能增加存储授权或存储设置入口。

## 授权和通知可见性

- 保留 `RECORD_AUDIO`（请求码 `1002`）和 Android 13+ `POST_NOTIFICATIONS`（请求码 `1003`）运行时授权链：先麦克风，再通知；全部确认前不勾选。拒绝、取消、空结果、权限名不匹配、异常数组或实际权限已撤销均不能开启。
- 相机保持原 `CAMERA` 请求码 `1001` 和原有逻辑。录音回调只修改录音开关，相机回调只修改相机开关；错误阶段、重复、已取消或未知录音请求码不应误开录音。
- 已有运行时授权仍要求应用全局 `NotificationManager.areNotificationsEnabled()` 为 true，且 `screen_off_recording_v1` 频道不是 `IMPORTANCE_NONE`。频道尚不存在时允许开启，由服务首次创建；设置页不创建或覆盖频道。通知管理器不可用时拒绝开启。
- 用户主动开启但通知可见性检查失败时，Toast 提示开启应用通知及录音状态通知频道，明确通知没有停止按钮。保留现有应用 / 频道通知设置跳转及包名、频道参数；返回后需再次主动开启。授权回调和 `onResume()` 不自动导航、不自动开启。已有设置入口不变，不新增跨包权限或其他设置入口。
- `onResume()` 在录音已开启但麦克风 / 通知授权、应用通知或频道任一失效时关闭录音开关；相机仍只按相机授权处理。恢复页面不请求权限、不弹提示。
- 保留 Manifest 中既有的麦克风、通知、FGS、wake lock 和相机声明；录音服务保持 `exported="false"`、`foregroundServiceType="microphone"`，不新增对第三方导出的录音入口或跨包权限。本次 UI 修改不编辑 Manifest。

通知权限仍是必要条件，即使通知没有停止按钮。不能以系统前台服务任务列表仍有提示为由放宽要求；服务仍须正常调用 `startForeground()` 并提交可见状态通知，实际通知和系统麦克风指示需真机验证。

## 系统限制与清理

遵循麦克风隐私、AppOps、运行时授权及音频资源策略。媒体 / 通话允许触发不等于绕过麦克风策略：麦克风被占用、隐私开关关闭、撤权或系统拒绝后台启动时，不伪装成功，也不启动原生录音机或授权 Activity 兜底。保留预检、开始失败、运行中错误、撤权、停止保存、文件处理和资源释放逻辑。

系统框架显式派发不等于应用自动获得麦克风授权；while-in-use 权限、后台 microphone FGS 豁免、目标 SDK、OEM 电池策略及静音策略均依赖系统。不得为维持录音点亮屏幕；最长 2 小时和已有有界 wake lock、启动 / 清理保护仍需集成验收。

## 集成后验收

1. 在目标 ROM 安装配套构建，仅启用系统框架作用域并按需重载；本次源码任务不安装、不重启、不操作设备。
2. 验证 idle 熄屏双击开始、idle 亮屏三击开始，以及 recording 两种屏幕状态均双击停止；切屏继续录音、快速重复操作和冷启动不误触发。熄屏操作不唤屏，现有相机逻辑无回归。
3. 核实通知仅显示状态且没有停止按钮，mic FGS 通知及系统麦克风指示保留；按键手动停止后文件保存至 `/storage/emulated/0/Download/oppose` 并可播放。验证最长 2 小时自动保存。
4. 媒体播放、通话时均检查快捷键可触发，同时记录系统拒绝 / 静音情况；不承诺通话同时录音成功。核实只录麦克风外部声音，无内部 / 下行捕获，扬声器外放可能被拾取。
5. 分别拒绝、取消、永久拒绝及撤销麦克风 / 通知权限，禁用应用或录音频道通知，验证开关及相机隔离。检查录音中撤权、隐私切换、资源占用、后台限制、存储失败的文件处理和资源清理，并记录真实系统版本和实测结果。
