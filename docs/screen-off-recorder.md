# 快捷麦克风录音（电源手势与控制中心磁贴）

## 开启和设置

HyperCeiler 总开关位于 **系统框架 → 音量 → 快捷麦克风录音**，默认关闭。为兼容已有配置，继续使用偏好键 `prefs_key_system_framework_volume_screen_off_recorder`；系统框架与设置 Hook 读取对应的不带 `prefs_key_` 前缀的桥接键。

- 仅使用息屏音量上快捷键：启用 Android 系统框架（`android`，运行于 `system_server`）作用域。
- 使用系统设置中的电源快捷键入口：同时启用 `android` 和系统设置 `com.android.settings` 作用域，按框架要求重载对应进程。打开 **系统设置 → 辅助功能 → 快捷手势 → 双击电源键** 下拉，主动选择 **录音**。只开启总开关不会自动改写原有电源键绑定。
- 两种入口共用总开关与录音服务，无需勾选原生录音机或 SystemUI，也不调用原生录音机。只勾选 `android` 时不能据此期待系统设置下拉显示新增选项。

电源下拉保留 ROM 当前可用的原生选项和“无”；切回其他选项后执行对应原生动作。该入口依赖目标 ROM 的快捷手势设置实现，缺失或不兼容时需记录机型与 ROM，不能把未出现的入口当作已通过验收。

## 控制中心录音磁贴

安装包含 `RecordingTileService` 的新版后，可在控制中心编辑页添加“录音”，或在 **HyperCeiler → 系统框架 → 音量 → 添加录音磁贴** 中请求系统确认添加。此按钮不依赖录音总开关；磁贴本身直接复用本应用录音服务，不需要 SystemUI 作用域。首次使用仍需先在 HyperCeiler 授予麦克风权限（原录音开关可发起授权）。不申请通知权限。

点击磁贴开始录音，再次点击停止并保存。磁贴副标题区分空闲、启动中、录音中、停止保存中和失败；状态来自服务实际生命周期，按键启动或停止也会同步。锁屏点击由系统解锁后执行。添加按钮调用 Android 的 `requestAddTileService`，最终是否添加由用户在系统确认框选择；不改写用户已有磁贴顺序。

磁贴点击只发送相同的 `ACTION_TILE_TOGGLE` 给非导出录音服务，服务串行判定开始、停止或忽略，避免依赖过时 UI 状态。磁贴经用户点击获得平台临时启动资格，使用普通 `startService` 投递；仅开始录音时提升为 microphone 前台服务。停止不会建立未履行的 foreground-service 启动合同。录音器仍遵循 RECORD_AUDIO、AppOps、麦克风静音、前台用户和系统麦克风隐私，并在开始前核验自己的实际录音 session／silenced 状态；并不从磁贴伪造系统侧隐私预检。

设备厂商对第三方磁贴的用户点击启动资格可能有差异；完整设备添加、锁屏和实际录音验收仍需安装后进行。尚未实测前，不将宿主测试等同于真机成功。

验证：`python3 tests/recording-tile/run.py` 使用真实 Android 35 public API 编译全部生产录音类，执行 401 项既有生命周期检查和 251 项磁贴检查；`python3 tests/recording-tile/negative_controls.py` 覆盖四项回归检出。

## 按键行为

| 屏幕状态 | 快速双击音量上 | 已绑定 HyperCeiler录音时双击电源键 |
| --- | --- | --- |
| 息屏 | 空闲时开始；录音中停止并保存（`TOGGLE`），均不唤屏 | 仅开始（`START_ONLY`）；录音中重复触发不停止 |
| 亮屏 | 所有音量键行为交还 OEM，不处理录音快捷键 | 仅开始（`START_ONLY`）；录音中重复触发不停止 |

原亮屏三击音量上开始录音已移除；亮屏双击音量上也不停止录音，亮屏的全部音量上/下行为由 OEM 处理。音量快捷键仅在息屏生效，不点亮屏幕。电源快捷键保留原生电源键亮屏、灭屏处理，不保证电源双击后屏幕状态不变，也不能用电源键重复触发来结束录音。

切换屏幕状态不结束录音。功能提供的手动结束方式为：点击控制中心“录音”磁贴，或先让屏幕息屏，再快速双击音量上。通知仅显示状态，没有停止按钮。按键触发不启动录音或授权 Activity。原有音量下相机功能及其授权逻辑保持。

媒体播放和通话期间也允许触发，不以播放或通话状态拦截；系统麦克风策略仍可能使录音静音或拒绝录音，不能保证通话同时录音成功。

## 权限、通知和录音文件

录音由 HyperCeiler 自身的非导出服务 `com.sevtinge.hyperceiler.recording.ScreenOffRecordingService` 执行，`foregroundServiceType="microphone"`。本功能的运行时授权仅需 `RECORD_AUDIO`（请求码 `1002`）。麦克风拒绝、取消、空结果、权限名不匹配、异常数组或实际权限已撤销均不能开启总开关；已取消、重复、未知和旧通知请求码 `1003` 不应误开录音。`onResume()` 只按麦克风授权校验录音开关，不自动请求权限或开启开关。

`POST_NOTIFICATIONS` 不是录音准入条件，也不要求应用通知或录音通知渠道开启；通知权限被拒绝、应用通知禁用、渠道重要性为零，均不得成为开启本功能的 UI 门槛。保留应用 Manifest 中其他功能使用的通知权限声明。本功能不弹通知授权、不导航至通知设置，也不通过 Toast 要求开启通知渠道。相机继续独立请求 `CAMERA`（`1001`），录音授权回调不得改变相机开关。

服务仍按 Android 要求创建通知渠道并调用 `startForeground()` 提交 microphone FGS 状态通知，系统麦克风指示仍保留。通知及麦克风指示的实际可见性由系统版本、权限、渠道和系统配置决定，不承诺通知始终可见，也不隐藏或绕过系统隐私提示。无需通知授权不代表省略前台服务通知调用。

仅使用 `MediaRecorder.AudioSource.MIC` 录制麦克风外部声音，不采集系统内部音频或通话下行，不使用播放捕获或通话音源；扬声器外放仍可能被麦克风拾取。文件通过 `MediaStore.Downloads` 保存至 `/storage/emulated/0/Download/oppose`，不新增存储权限或 `MANAGE_EXTERNAL_STORAGE`。保留最长单次 2 小时后自动停止保存，以及错误、撤权、停止后的文件处理和资源清理。

## 系统限制

遵循麦克风隐私、AppOps、运行时授权及音频资源策略。系统框架显式派发不等于自动授予麦克风权限；while-in-use 权限、后台 microphone FGS 豁免、目标 SDK、OEM 电池策略及静音策略仍依赖系统。麦克风占用、隐私开关关闭、撤权、后台启动拒绝或存储失败时，不伪装成功，不启动原生录音机或授权 Activity 兜底。

音量快捷键不得为维持录音点亮屏幕；电源键仍由原生电源管理处理亮灭屏。已有有界 wake lock、预检、启动失败、运行中错误、撤权和停止清理保护需随服务实现进行集成验收。

## 离线验证

在仓库根目录执行：

```sh
python3 tests/recorder-ui-v2/run.py
git diff --check
```

`recorder-ui-v2` 保留旧目录名以兼容现有命令，检查 v3 默认/简中文案、旧通知提示删除、资源引用、默认关闭、Manifest 服务类型及请求码。它使用临时 Android/Preference fixture 以 `javac --release 17` 编译实际 `VolumeSettings.java`，执行仅麦克风授权、各种通知状态不设门槛、相机隔离、无效或过时回调、撤权与恢复页面的测试。测试 README 说明具体覆盖范围。

手势 Hook、系统设置下拉和服务分别另有 `tests/recorder-volume-v3`、`tests/power-double-click-recorder`、`tests/power-recorder-settings` 和 `tests/recorder-service-v2` 回归套件。UI 文案测试不执行真实设备、PrefsBridge 持久化、Hook、MediaRecorder、MediaStore、系统通知或音频 HAL，不代表完整 Gradle/APK 构建或真机录音成功。

## 真机集成验收

1. 安装配套构建并启用总开关，先只勾选 `android`，验证息屏双击音量上开始、再次双击停止保存且全程不唤屏。亮屏单击、双击、三击和长按音量上/下都应保持 OEM 行为，录音中亮屏双击也不停止；原音量下相机逻辑无回归。
2. 加入 `com.android.settings` 作用域并重载，验证指定系统路径出现双击电源键下拉，能选择录音，同时保留原生选项。进入/恢复页面不自动覆盖原绑定，选择后再进页面显示一致，切回其他选项恢复对应原生动作。
3. 在亮屏与息屏分别双击电源键，确认只开始录音，已有录音时重复触发不停止；原生电源亮灭屏行为保留。切屏继续录音，先息屏再双击音量上能停止并保存。检查冷启动、快速重复操作及两个入口交替时没有重复录音会话。
4. 分别拒绝、取消、永久拒绝和撤销麦克风权限，验证总开关与相机隔离。拒绝通知授权、关闭应用通知或录音渠道时仍可开启录音；确认服务仍调用 FGS 通知，记录实际通知和系统麦克风指示的可见性，不以文案推断始终可见。
5. 检查保存目录、文件可播放、最长 2 小时自动保存、状态通知无停止按钮。媒体播放和通话中验证快捷键能触发，记录系统拒绝或静音情况；确认仅录麦克风外部声音，外放可能被拾取。
6. 检查录音中撤权、麦克风隐私切换、资源占用、后台限制与存储失败的文件处理及资源释放。记录真实设备、ROM/Android 版本、作用域和测试结果；离线通过不替代以上实测。
