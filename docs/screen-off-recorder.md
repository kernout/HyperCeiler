# 熄屏双击音量上录音

## 预期行为与作用域

入口为 **系统框架 → 音量 → 熄屏双击音量上录音**，偏好键为 `prefs_key_system_framework_volume_screen_off_recorder`，默认关闭。启用模块时只需勾选 Android 系统框架（Android 系统 / `android` / `system`，运行于 `system_server`）作用域，无需勾选录音机、SystemUI，也不调用原生录音机。

配套 Hook 应在熄屏且无媒体播放、无通话时，识别音量上快速双击并切换开始 / 停止录音；停止时保存。开启此选项后，熄屏音量上键由录音快捷键占用，单击和长按也不唤屏。触发、录音和停止均不应启动 Activity 或点亮屏幕。媒体播放或通话时不触发快捷操作，具体按键门禁和 ROM 兼容性须由配套 Hook 验证。

录音由 HyperCeiler 自身的独立后台录音服务 `com.sevtinge.hyperceiler.recording.ScreenOffRecordingService` 执行；“后台”不代表隐藏前台服务或系统隐私提示。再次熄屏双击音量上，或点击录音通知的停止按钮，应停止并保存到 `Recordings/HyperCeiler`。单次最长 2 小时，到达上限应自动停止并保存。录音启动后允许亮屏继续录音，亮屏本身不应取消；亮屏时可用通知停止，也可再次熄屏后双击停止。这些是集成后的验收要求，不是本次设置层测试已验证的录音结果。

## 权限与设置状态

- HyperCeiler 需要 `RECORD_AUDIO`（请求码 `1002`）和 Android 13+ 的 `POST_NOTIFICATIONS`（请求码 `1003`）授权。用户点击开启时先检查麦克风，未授权则先请求麦克风；麦克风授权成功后若通知未授权，再请求通知。两项授权和实时状态全部确认前均不勾选。拒绝、取消、空结果、权限名不匹配、数组异常或实时权限失效都不能开启。
- 相机保持原请求码 `1001` 和原有 `CAMERA` 权限链。录音的 `1002` / `1003` 结果只修改录音开关；相机结果只修改相机开关。录音只接受当前待处理阶段的回调，错误阶段、重复或已取消的录音回调不能误开开关；未知请求码不修改任一开关。
- 已取得运行时授权还必须满足应用全局 `NotificationManager.areNotificationsEnabled()` 为 true，且 `screen_off_recording_v1` 频道未被设为 `IMPORTANCE_NONE`。频道尚不存在时允许开启，由服务首次创建；设置页不创建或覆盖频道。若通知管理器不可用则拒绝开启。
- 仅在用户点击开启、运行时授权已有但通知门禁失败时，显示 Toast 提示开启应用通知及录音频道，打开 `ACTION_APP_NOTIFICATION_SETTINGS`；若仅录音频道被禁用则打开 `ACTION_CHANNEL_NOTIFICATION_SETTINGS`，传递应用包名和对应频道 ID。返回后需用户再次点击开启，不自动勾选。授权回调发现通知门禁失败时保持关闭，不自动导航；用户再次点击开启可进入对应设置。系统设置入口不可用时保留提示并保持关闭。
- 页面 `onResume()` 分别检查相机和录音条件。已开启录音但麦克风 / 通知授权、全局通知或频道门禁任一失败，仅关闭录音开关；相机仍只按相机权限处理。恢复页面不请求权限、不弹提示、不启动设置 Activity，也不会自动开启已关闭的开关。页面外即时撤权和服务运行期间的终止 / 保存仍需系统与配套实现处理。
- Manifest 已有 `POST_NOTIFICATIONS`，不重复添加。本功能使用 `RECORD_AUDIO`、`FOREGROUND_SERVICE_MICROPHONE`，保留既有 `FOREGROUND_SERVICE`、`WAKE_LOCK` 和相机声明。录音服务为 `exported="false"`、`foregroundServiceType="microphone"`，不新增签名权限或对第三方导出的录音入口。

当前服务要求可见的录音通知，以便用户能查看录音状态并停止保存；通知权限及应用 / 频道门禁是开启本功能的必要条件。不能仅以 Android 在前台服务任务管理界面仍有系统提示作为允许录音的依据。服务仍须正常调用 `startForeground()` 并提交带停止操作的通知，不隐藏通知或麦克风指示；系统实际通知呈现仍需真机验证。

## 麦克风隐私和后台限制

必须遵循系统麦克风隐私、AppOps、运行时授权和音频资源策略。隐私开关关闭麦克风、撤销授权、麦克风被占用或系统拒绝后台启动时，不应绕过限制，也不应启动原生录音机 / 授权 Activity 来兜底。预检和实际录音之间仍可能改变权限或隐私状态，应由服务处理开始失败、运行中失败、停止、保存和资源释放；不伪装成功。

非导出服务应由系统框架侧显式调用。系统进程派发不等同于自动获得 `RECORD_AUDIO`，也不保证所有 Android / HyperOS 版本都允许从后台启动带 microphone 类型的 FGS。尤其 Android 的 while-in-use 麦克风权限、后台 FGS 启动豁免、目标 SDK 和 OEM 电池策略必须在目标设备实测；本次不新增签名权限，也不承诺绕过这些限制。不得为了维持录音而点亮屏幕；仅有 `WAKE_LOCK` 声明也不能证明服务已正确使用有界的 partial wake lock。

## 已验证范围与运行方法

本次编辑范围为应用 Manifest、`VolumeSettings.java`、音量设置 XML、默认 / 简中应用字符串及本说明，另附 `tests/screen-off-recorder-permission` 的离线测试。录音 service / hook 是配套实现，不在本次编辑或测试覆盖范围；已有相机 service / hook 不作改动。

在仓库根目录执行：

```sh
python3 tests/screen-off-recorder-permission/run.py
```

测试在 Linux 临时目录中，以 `javac --release 17` 编译并执行实际 `VolumeSettings.java`，使用最小 Android / Preference fixture。覆盖开关申请、拒绝 / 授权 / 取消、请求码隔离、错误权限名和数组、授权回调与实时权限不一致、三种权限组合、通知全局 / 频道门禁、设置 Intent 及页面恢复撤权、未初始化页面及关闭后不被无关授权误开。同时解析 Manifest / 设置 / 两套字符串 XML，检查默认值、键和资源引用链、麦克风服务类型与非导出声明、已有 FGS / wake lock / 相机权限保留，以及相机 `1001`、麦克风 `1002`、通知 `1003` 的授权链隔离。详见测试 README。

这些是设置和权限分流的宿主测试，不执行真实 Android 权限对话框、PrefsBridge 跨进程同步、Binder、Hook 按键分发、MediaRecorder、音频 HAL、MediaStore 或系统通知。未通过此测试声称完整 Gradle / APK 构建成功，更不能声称已经真机熄屏录音成功。
