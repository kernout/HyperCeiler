# 息屏拍照亮屏续拍与持久 FIFO

本版本继承 `56f3e60158aa747ac959dc8c8c17b8bb0dd58331` 的录音开机选择修复、离线功能与相机诊断。

## 行为

- 仅在 OEM 音量下 `count == 2` 回调入口判定息屏。每次有效双击分配独立 UUID，保留入口时间与用户快照；移除 2500ms 拍摄冷却及 dispatchPending 忙丢弃。
- Handler 派发后亮屏不撤销已经接纳的息屏请求。服务不再监听亮屏取消，Camera2 控制器也不再以亮屏作为中止条件。亮屏时新产生的双击仍走 OEM 行为。
- 每次请求在服务收单时校验 UUID、入口息屏标记及 2.5 秒新鲜度和系统隐私 preflight；持久入队后，排队等待不会因超过该新鲜度而过期。
- 请求先写应用私有目录的同步 receipt，再原子重命名确认接收。至多 128 个未完成请求、4096 个历史 receipt；重复 UUID 不二次拍摄。达到容量或落盘失败会明确报告拒绝，不假称接收成功。
- 逐张 FIFO，前一个 Camera2 设备关闭后才启动下一张；每次操作有 15 秒超时和最多 3 次尝试。故障清理挂起时暂停队列，保留持久记录，避免同时占用多个相机。
- 有效 JPEG 先写私有 spool 并同步落盘，再发布至 `DCIM/Camera/HC_<UUID>.jpg`。MediaStore 写入或发布失败保留 JPEG，只重试发布，不为同一张重新曝光；唯一名称用于恢复 insert 与 receipt 之间的进程中断窗口。
- 系统 redelivery 或下一次有效请求可恢复未完成持久任务；不注册开机偷偷拍照。用户切换、退出前台用户、权限撤销或系统相机禁用会终止相关拍摄并记录原因。
- 前台通知显示待处理数量；失败有明确日志和通知。保留相机权限、隐私和 AppOps 检查，不启动 Activity，不伪造成功或生成空白占位文件。

## 速度与可靠性边界

约 300ms 是接收独立双击请求的目标节奏，不承诺相机传感器每 300ms 完成曝光。当前实现逐张打开、预览测光、拍摄、保存和关闭，因此队列可能积压，后面的照片会在实际轮到时曝光，而不是还原按键瞬间的画面。

亮屏本身不再丢弃已接收请求。硬件错误、相机被其他应用抢占、权限/隐私关闭、磁盘耗尽、系统不再重启服务或进程被杀仍不能保证每个请求最终得到照片。失败不会冒充成功；已取得的 JPEG 会保留用于重试，超过重试上限的请求留有失败记录。应用私有 spool/receipt 位于 `files/screen-off-capture-queue/`。

## 验证

使用真实 Android API 35 public SDK 与 HiddenApiBypass 6.1 编译全部生产 camera 源码。主机测试执行实际队列、服务、发布器和控制器，用 Android/Camera2 边界替身，不访问真实设备相机。

- 75 项持久 FIFO 断言：入队、重启恢复、去重、唯一命名、JPEG 校验及重试。
- 57 项实际服务/发布器生命周期断言：30 个以 300ms 节奏到达的请求 FIFO 保存、忙时不丢、亮屏收单、失败保存 JPEG、重启恢复、超时和用户切换。
- 17 项实际控制器生命周期断言：亮屏继续、权限撤销、spool 恢复发布、发布失败保留 JPEG、进程门闩释放。
- 234 项实际 hook 断言与 24 项录音/相机按键共存断言：0/300/600ms、边界间隔及多个未 drain 请求均独立派发，post 后亮屏继续，新亮屏事件走 OEM，用户/隐私变化仍拒绝。
- 17 项主摄选择/方向及 9 项服务新鲜度断言。

这不是实机曝光成功率或硬件吞吐测试；尚未安装、重启或触发设备拍照。
